1. 这个 App 适合什么人？

1.1 我们把健身水平分成 5 档

档位这是谁特征
L1 零基础 从没系统训练过 不会基本动作、没有训练习惯。需要先学动作、建立训练频率
L2 跟课/团课 偶尔上私教/团课 知道几个动作但不主动设计、不记录、不研究"为什么"
L3 学习型自主 ← 目标用户 有 1+ 年基础，想自己设计计划，愿意学原理，希望靠数据判断而不是凭感觉
L4 经验型 3+ 年训练，已有体系 自己读论文、自己设计周期。FitLab 能用但不是强需求
L5 专业 运动员 / 教练 用专业软件、有团队支撑，FitLab 不在他们工具栈里

1.2 适合谁？

✓ 你符合这些特征，FitLab 就适合你：
  • 有一点健身基础（至少能完成深蹲、卧推等基本动作）
  • 愿意学一些健身原理（不是只想"被告诉做什么"）
  • 想自主训练，希望理解为什么这样安排
  • 需要一个工具帮你记录训练数据 + 判断计划合理性 + 看数据分析
  • 愿意每周花 ~10 分钟记录和复盘

1.3 不适合谁？

✗ 这几类用户用 FitLab 不会有好体验：
  • 完全零基础（L1）—— 需要先找教练学动作，FitLab 不教你怎么做深蹲
  • 只想跟练不想研究（L2 但不愿学）—— Keep / Fittime 那类视频跟练 App 更合适
  • 有伤需要康复—— 个性化 RA/PT 程序，FitLab 用的是群体均值数据
  • 明显体态失衡或慢性疼痛—— 先解决医学/姿势问题，再来用
  • 只追求"减脂数字"—— FitLab 不管饮食，体脂率是系统问题

1.4 它能做的 vs 做不了的

✓ 能做✗ 做不了
• 基于你的目标 + 历史 + 时间预算 生成完整 10 周训练计划
• 计划生成时自检：每块肌肉训练量是否够、平衡比率是否健康、时间是否撑得住
• 记录每次训练（重量/次数/组数/RIR/自评）
• 多时段复盘（日/周/月/季/年）
• 把抽象训练原理（MEV/平衡/渐进等）翻译成你的真实数据
• 教你训练科学原理（16 条带原文出处） 		• 不能纠正动作姿势——它看不到你怎么做的
• 不能评估发力是否到位——靠你自填 RIR
• 不处理伤病/康复——你需要康复师/PT
• 不针对体态失衡个性化——默认数据是群体均值
• 不管饮食/减脂——只看训练
• 不能替代教练对动作的现场反馈
📌 关键限制：FitLab 的所有数据假设（如"胸大肌 MEV = 6 组/周"）基于群体平均。要做个性化，你需要先训练 4-6 周，让系统从你的实际反馈中调整。第一个周期跑完后，App 会建议"你的个人 MEV 系数"，从此评估更准。

2. 它怎么评估一个训练计划好不好？

这部分回答"如果你给 FitLab 一份计划，它会从哪几个维度看？"

2.1 底层逻辑：肌肉是怎么长大的

身体里所有"长肌肉"的动力来源就 3 个：

  1. 力学张力——肌肉承受足够大的力（最主要）
  2. 代谢应激——足够时间堆代谢副产物（"泵感"）
  3. 肌肉损伤——离心阶段产生微撕裂，修复后变粗

要让肌肉长，这 3 个机制都得被触发。这就要求训练有足够重量 + 足够次数 + 接近力竭。然后训练完 36-48 小时内是"长肉窗口"（肌肉蛋白合成 MPS 高峰），过了就回基线。

2.2 每个动作 = 多块肌肉参与，按"打折"算

"做了 1 组深蹲" 不等于 "练了 1 组股四"——一个动作往往同时刺激多块肌肉，按解剖激活程度打折分配给参与的肌肉：

1 组杠铃后蹲贡献给：系数
股四头肌-外侧+中间头1.0（主肌）
臀大肌-下部0.8（强协同）
股直肌0.5
内收肌0.4
竖脊肌0.3
腘绳肌0.3

所以 3 组深蹲 = 给股四 3.0 组、给臀大肌 2.4 组、给内收肌 1.2 组...... 加上其它动作的贡献，一周下来每块肌肉的"周有效组数"就清楚了。

2.3 每块肌肉需要：足够强度 + 足够频率

维度标准
强度 单组要"重量 ≥ 65% 1RM" + "次数 6-15" + "RIR ≤4"——满足这 3 项才算 1 个有效组。
来源Schoenfeld & Grgic 2018
训练量 每块肌肉每周要做多少有效组才能增肌？这有 3 个门槛：
• MEV（最低有效量）—— 低于它白练
• MAV（最佳量）—— 长得最快的甜区
• MRV（最大可恢复量）—— 超过它恢复跟不上
不同肌肉数字不同：背阔肌 MEV=10、肩袖 MEV=4
频率 每块肌肉每周训 ≥2 次比 1 次效果更好（容量等同时）。因为 MPS 窗口只 36-48h，每次训练只开一次窗。
来源Schoenfeld 2016

2.4 肌肉之间要平衡，不平衡会怎样？

身体是个杠杆系统——每个关节两边都有相反方向的肌肉拉。如果一边训太多、另一边太少，关节会被"拉偏"，长期会出问题：

比率健康区间失衡后果
胸 / 背0.6 - 1.2胸太强 → 圆肩 / 头前伸 / 长期颈痛
推 / 拉0.85 - 1.2推 >> 拉 → 肩袖磨损 / 肩痛
Q/H（大腿前/后）1.0 - 1.7股四 >> 腘绳 → 前交叉韧带 (ACL) 损伤风险
上身 / 下身0.5 - 1.3极端失衡 → 体型不协调，下身基础不稳
前链 / 后链0.7 - 1.3久坐多偏前链 → 慢性腰痛

FitLab 评估计划时看这 10 个比率是否在区间内。不在的话，要么自动加动作修复，要么明确告诉你这是"权衡"（如增肌取向天然上身偏多）。

2.5 一个完整例子：评估"30 节增肌计划"

假设：用户做完计划阶段二（W4-7），一周练 3 次（课型 A/B/C），每动作 3 组。FitLab 怎么评估？

步骤 1 · 算每块肌肉的周训练量

对 42 块肌肉，每块都用"动作组数 × 该动作对它的贡献系数"加总。例如：

  • 背阔肌：A 课引体 3×1.0 + B 课划船 3×1.0 + C 课单臂划船 3×1.0 = 9.0 组/周
  • 三角肌中束：B 课侧平举 3×1.0 + 推举 3×0.5 = 4.5 组/周
  • 比目鱼肌：A 课站姿提踵 3×0.5 = 1.5 组/周

步骤 2 · 对照 MEV 门槛

肌肉实际MEV判断
背阔肌9.010🟡 接近 MEV (90%)
三角肌中束4.58🔴 不足 (56%)
比目鱼肌1.56🔴 严重不足 (25%)

步骤 3 · 检查 10 个平衡比率

  • 胸/背 = 19.4/36.9 = 0.52 ⚠（目标 0.6+）
  • Q/H = 15.9/8.1 = 1.96 ⚠（目标 ≤1.7，膝健康风险）
  • 其它 8 个比率检查...

步骤 4 · 教练给出诊断 + 调整方案

👨‍🏫 教练说：
"这个计划主要肌群已经合格（背阔/股四/臀大/胸大都 ≥ MEV）。但有 2 个真问题：① 比目鱼肌严重不足（站姿提踵主要练腓肠肌不练比目鱼）→ 建议加坐姿提踵；② Q/H 失衡 1.96 → 建议加俯卧腿弯举。

另 2 个看似失衡其实可接受：胸/背 0.52 对久坐人群是好纠偏（不修）；上身/下身 1.9 是增肌取向天然结果（接受）。"

这就是 FitLab 评估计划的完整逻辑——把抽象的"训练原理"翻译成具体的、每个数字都能追问"为什么"的诊断。

3. App 工作流程：输入 → 处理 → 输出

这部分讲 App 内部怎么运转的——你给它什么，它怎么算，给你什么。

3.1 输入 · 你给系统什么信息

类型具体字段
个人数据 身高、体重、年龄、性别、单位偏好
训练目标 主要目标（增肌/力量/耐力/健康维持）
具体里程碑（如"完成 1 个 strict 引体"）
训练计划参数 频率（2-5 次/周）· 单次时长（30/45/60/75 分）· 周期（4/8/10/12 周）
历史训练（如有） 过往动作记录（重量×次×组）· 系统据此算 e1RM 作为起步重量参考
偏好与限制 排除的动作（如膝伤不深蹲）· 设备约束（家训练 vs 商业健身房）
身体数据 定期体重、围度、体脂（可选，但有助于跟踪长期趋势）

3.2 数据库 · 系统知道什么

FitLab 的核心数据库（基于训练科学）：

数据集包含什么
动作库
EXERCISE_DB		 40+ 个动作。每个动作有：
• 名称、英文、动作族、难度
• contrib 系数：这个动作对每块肌肉的贡献（0-1）
• 教学要点、推荐重量范围、退/进阶
• 系数来自 EMG 研究 + 解剖学 + 业界共识
肌肉门槛表
MUSCLE_TARGETS		 42 块肌肉。每块有：
• MEV / MAV / MRV 三个训练量门槛（数字基于 Renaissance Periodization 框架 + Schoenfeld 2017 剂量-反应曲线）
• 父肌肉 / 子部位关系
平衡比率定义 10 个比率。每个有：
• 计算公式（哪些肌肉相除）
• 健康区间 + 失衡后果
• 文献依据（Cools 2007 / Q/H 研究 / Janda 等）
训练原理库 16 条原理（6 条底层生理 + 10 条训练原则）。每条带：原文引用 / PubMed 链接 / 通俗解释 / 在系统里的具体应用
公式 • e1RM 估算（Epley/Brzycki）
• RIR 强度衡量（Zourdos 2016）
• 有效组判定（Schoenfeld & Grgic 2018）

3.3 处理 · 约束求解 + 自检

这是 App 最核心的部分——计划生成不是"挑动作"，是约束求解问题。

步骤 1：算个人化目标

把默认 MEV/MAV/MRV 乘以"个人 MEV 系数"（默认 1.0，4 周训练后自动调整）。例如背阔肌默认 MEV=10，你系数 1.3 → 你的个人 MEV = 13。

步骤 2：候选动作池 → 解约束

从 40+ 动作里选最少动作满足所有 MEV。优先选复合动作（一个动作覆盖多块肌肉，效率高）：

硬约束（必须满足）：每个主肌周量 ≥ 个人 MEV · 单次时长 ≤ 用户预算 · 同肌肉间隔 ≥ 24h · 排除项不出现
软约束（尽量满足）：≥ 7/10 平衡比率在区间 · 主肌频率 ≥ 2 次/周 · 复合优先 · 疲劳总量受控

步骤 3：分配到课型 + 安排周期

把选出的动作分到 N 个课型（如 A/B/C），保证每块主肌每周练到 ≥2 次。再加 3 阶段周期化（重建 → 主训 → 强化 → 减载）和渐进超负荷（每周 +2.5kg 或 +1-2 次）。

步骤 4：跑自检

用 Q2 节的评估逻辑检查生成的计划：

  • 跑 MEV 检查：所有主肌 ≥ MEV ✓
  • 跑平衡检查：≥ 7/10 比率合格 ✓
  • 跑时间检查：每课时长 ≤ 预算 ✓
  • 跑频率检查：主肌 ≥ 2/周 ✓

步骤 5：协商权衡（如必要）

有些约束天然冲突（例：增肌目标 + 30 分/次 + 6 课型 ≠ 能覆盖全部 MEV）。这时系统明确告诉用户冲突，给 2-3 个选项让用户选：

  • ① 加时长？
  • ② 接受部分肌肉不达 MEV？
  • ③ 加频率？
关键设计原则：系统不替用户做价值权衡，而是把权衡的代价讲清楚让用户决定。

3.4 输出 · 你得到什么

输出是什么
完整训练计划 10 周 × 3 次/周 = 30 节课的逐节细节：每节 6-7 个动作 · 每动作的重量/组数/次数/RIR
计划评估 设计层评估（理论上每块肌肉训练量、平衡比率）。在 P6 屏可查看。

4. 为什么会有这个 App？开发者的故事

健身背景

非健身专业教练或从业者。健身一直在超级猩猩上课、上过 30 节私教课。平均每月 5-20 次健身，根据时间和身体情况，多时多、少时少。

为什么做这个东西

1. 过去半年多健身效果不好。

觉得自己花了挺多时间健身，但历时半年多——身体围度没太大变化，还胖了好几斤。身体成分测试虽然有变化，但那个秤的误差非常大（一周肌肉重量可以增长一两公斤）。

个人认为用健身房单次的身体成分测试数据代表效果，就是自欺欺人。

2. 教练也没想象中靠谱。

第一，目标设计就不对，但教练没有告诉我。最初健身的目标是按体脂率看的——稍微研究一下发现体脂率不是上几节课就能达成的，它涉及平时生活/饮食/运动整体的系统问题。

第二，过去 30 节课我学了 100 多个新动作。现在想追踪历史的进步，完全追不出来——因为每节课都在学新动作，感觉上了 30 节体验课。

第三，上了两个月之后，每次去上课都很烦躁。没有正反馈——没觉得力量变了、体能增了。反而是耐心逐渐变差、越来越不想去上课，两三个动作之后就不想再动了。

从来没追问过为什么。

从来没追问过"为什么每节课要练这些"、"为什么是这个次数"、"为什么是这个重量"。

觉得我已经找了这里看起来最厉害的教练了，我就不用再自己研究这些问题了。

结果发现并不是。

这个 App 的初衷：用一个工具，把"为什么这样训练"讲清楚，把"训练效果到底怎么样"用数据真实呈现。让自己（也让其他和我有类似困惑的人）不再只是"觉得自己练了"，而是看到自己确实在变化或确实没在变化，并且知道原因。
